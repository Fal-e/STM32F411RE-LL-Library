# v0.1.0 - revived public maintenance baseline

This release is the revived public maintenance baseline for `STM32F411RE-LL-Library`.

It focuses on repository clarity, licensing, documentation, review workflow, CI hygiene, examples documentation, and release readiness. It does not claim that the firmware has been rebuilt, flashed, or hardware-tested as part of the revival work.

## What Changed

### Repository Metadata And Maintenance

- Added the MIT license.
- Rewrote the README with project status, supported target, folder structure, examples, limitations, roadmap, contributing, and license notes.
- Added contributing guidance and a code of conduct.
- Added GitHub issue and pull request templates.
- Added maintainer guidance for embedded C review expectations.
- Added third-party notices for bundled CMSIS/ST/vendor files.

### Build, CI, And Repository Hygiene

- Added build/import notes for STM32CubeIDE and TrueSTUDIO-style project import.
- Added lightweight GitHub Actions checks for repository documentation and metadata.
- Added a root `.gitignore`.
- Removed generated Eclipse workspace metadata and generated Debug build outputs from source control.

### Examples And Scope

- Added examples documentation for the current STM32F411RE examples and helper modules.
- Documented GPIO, ADC, I2C, LCD, timer/delay, and timer-stub status from the current source tree.
- Added scope documentation that identifies `GPIO_Driver/`, `Tutorial1/`, and `Timers/` as STM32F411RE project folders.
- Labeled `stm32_ssbp/` as legacy STM32F103/Blue Pill reference material.

### Release Preparation

- Added this v0.1.0 release note.
- Added `ROADMAP.md`.
- Added `RELEASE.md` with the release checklist and GitHub release steps.
- Updated `CHANGELOG.md` for the v0.1.0 baseline.

## Verified For This Baseline

Verified during the maintenance work:

- Documentation and metadata files are present.
- Lightweight repository checks pass in GitHub Actions.
- Required documentation links are present in the README.
- Generated `.metadata/` and `Debug/` outputs are no longer tracked.
- New documentation states current verification limits instead of implying hardware results.
- No source code, vendor code, linker script, startup file, or hardware-facing behavior was intentionally changed for this baseline.

## Not Yet Verified

Toolchain and build items that still need verification:

- STM32CubeIDE import for `GPIO_Driver/`, `Tutorial1/`, and `Timers/`.
- TrueSTUDIO import/build on a matching legacy setup.
- Command-line `arm-none-eabi-gcc` build.
- Exact compiler version, flags, include paths, linker flags, and source lists.
- Firmware compile CI.

Hardware items that still need verification:

- GPIO blink behavior on an STM32F411RE board.
- ADC input behavior on PC0.
- I2C1 behavior on PB6/PB7.
- LCD I2C backpack address and bit mapping.
- LCD 4-bit parallel wiring and behavior.
- Timer/delay accuracy.
- MPU6050 helper behavior.

Legacy material that still needs a decision:

- Whether `stm32_ssbp/` should remain as legacy reference material, move to an archive folder, or be removed in a future cleanup.
- Any STM32F103/Blue Pill build or hardware behavior.

## Known Limitations

- A verified command-line build system is not present yet.
- IDE import instructions are documented but still need to be tested on a clean setup.
- CMSIS/ST vendor files are duplicated across project folders.
- Some source comments and names still reflect the original older project state.
- Driver behavior has not been fully audited.
