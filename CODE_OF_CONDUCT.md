# Code of Conduct

This project is maintained as a respectful, practical open-source space for embedded C, STM32 learning, and careful project revival.

## Expected Behavior

Participants are expected to:

- Be respectful and constructive.
- Keep feedback focused on the code, documentation, tests, or hardware evidence.
- Assume good intent while still being precise about risks and defects.
- Be honest about what was tested, what was not tested, and what needs verification.
- Make space for beginners and experienced contributors alike.

## Unacceptable Behavior

The following behavior is not acceptable:

- Harassment, insults, threats, or personal attacks.
- Discriminatory language or behavior.
- Publishing private information without permission.
- Repeatedly derailing technical discussions.
- Misrepresenting test results, hardware validation, usage, adoption, or project status.

## Hardware and Safety Discussions

Embedded projects can affect real hardware. Disagreements about safety, wiring, clock setup, voltage, timing, or peripheral behavior should be handled with extra care.

When in doubt, document the uncertainty and ask for verification instead of treating assumptions as facts.

## Reporting Problems

If you see behavior that violates this code of conduct, contact the repository maintainer through GitHub. If private contact is not available, avoid posting sensitive personal details publicly and use GitHub's reporting tools when appropriate.

Maintainers may remove comments, close threads, request changes, or restrict participation when needed to keep the project constructive.
